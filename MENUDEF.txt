// ============================================================================
// RS_VR_Weapons -- the test shotguns' options, laid out like the pistols' page
// in the reload system: a page per gun, then the shared pages (hands, ovals,
// rounds, pouch, firing) that work for whatever gun is in your hand.
//
// Added to the engine's own OptionsMenu, not to the reload system's page: an
// AddOptionMenu naming a menu that does not exist stops the engine at startup,
// and this package must never be able to do that to the reload system. The
// Submenu links below only open the reload system's pages, which is safe:
// RS_VR_Reload always loads first, and a missing Submenu target is only a dead
// row, never a startup error.
//
// Every slider here is checked by tools/menu_lint.py on each build.
//
// A GUN PAGE'S HAND ROW OPENS ITS TYPE'S PAGE (WM_HS_<Type>, RS_VR_Reload): the hand seats
// are per kind of gun, so the pump's row opens the shotgun's. The hub pages keep
// "Your hand on each gun", which opens the reload system's type picker.
//
// SO DOES ITS AMMO ROW (WM_HA_<Type>, RS_VR_Reload 09-13 15:39, FEEL_PLAN row 3): a magazine,
// shell, cell or round in the hand and on the floor is placed per kind of gun too. The hub
// pages keep WM_MagMenu, which is now the reload system's links to all fourteen.
// ============================================================================

// ONE ENTRY IN THE OPTIONS LIST, NOT TEN.
//
// This used to add eight lines here, and each weapon set added a ninth, tenth and
// eleventh of its own -- eighteen rows all starting "VR Weapons --", filling the
// options list and burying every other mod's menu under them. Nothing about it said
// which row was the one you wanted.
//
// Everything now hangs off one row. A new set adds itself to WM_PlaceHub below and
// the options list does not grow.
AddOptionMenu "OptionsMenu"
{
	Submenu "VR Weapons", "WM_Hub"
}

OptionMenu "WM_Hub"
{
	Title "VR WEAPONS"
	// TWO ROWS. There are only two things anyone comes here to do: get the guns, or
	// move a gun in your hand.
	//
	// STRAIGHT TO THE THING, not to the page that explains the thing. "Give me a set"
	// was the last line of a twelve-line wall of text about how new games start, which
	// is a fine thing to be able to read and a terrible thing to have to read first.
	Submenu "Give me a set of weapons", "WM_GiveSetMenu"
	Submenu "Where each gun sits in your hand", "WM_PlaceHub"
	StaticText ""
	// THE TEST BENCHES ARE OFF THE MENU (owner, 2026-09-25: "too many useless and
	// redundant options"). They were seven rows of scaffolding -- rooms full of one
	// kind of gun, built to check a family while it was being fitted -- sitting in
	// front of a person trying to play. WM_TestHub below still exists and still
	// works; nothing links to it, so nothing shows it. Put this row back if the
	// benches are wanted again:
	//     Submenu "Test benches", "WM_TestHub"
	//
	// WM_WeaponSetMenu is likewise off the menu: it explains how a new game starts,
	// which is a thing to read once, not an option to set.
}

// WHERE EACH GUN SITS -- one page per weapon set. The sets each add their own row to
// this menu from their own MENUDEF, so a set that is not loaded adds nothing and this
// page shows exactly what you have.
// WHERE EACH GUN SITS -- AND IT IS NOT A MENU ANY MORE.
//
// This used to be 145 pages and 1,451 sliders: ten per gun, position, rotation and scale,
// one hand-written page per weapon across eleven files. They existed for one reason --
// there was no way to move a gun from inside the game, so the only way to reach a gun's
// placement cvars was a page that named them.
//
// AND THEY WERE THE WRONG TOOL FOR THE JOB THEY EXISTED FOR. Opening a menu pauses the
// game: the gun stops being held, your hand stops moving, and the one question being
// answered -- does this gun sit right in my hand -- cannot be seen while nothing moves.
// Fitting a gun by dragging a slider is fitting it blind.
//
// The sticks do it instead (RS_WorldHands, rs_ovaledit.zs), live, with the gun in your
// hand. They write THE SAME cvars these sliders wrote, so nothing is lost and nothing
// needs migrating -- every value already tuned is still exactly where it was.
//
// Removed 2026-09-25 on the owner's instruction: "all i know i have 2k lines of gun
// options and i don't need them". Restore point: git tag pre-menu-strip.
