# ============================================================================
# RSBDEFS -- RS_VR_BD22's own profiles.
#
# This set owns everything it uses. A profile here is BD22's and nothing else
# reads it, which is why it is a NEW NAME rather than an override of `rail`:
# redefining `rail` would silently change Vanilla's railgun for anyone who
# happens to have BD22 in the load order, and a look that changes depending on
# what else is loaded is the hardest kind of fault to report.
# ============================================================================


# ---------------------------------------------------------------- TRAILS

# THE BD22 RAILGUN, turned up. The owner, 2026-10-02: "the railgun visual fx is
# ass right now and it needs brought upo to 11".
#
# WHAT IT WAS. `trail rail` is the Quake 2 one: a 0.6-thick core, a 3.5 halo,
# intensity 2.2, four small lights. It is restrained on purpose because it was
# written for a flatscreen railgun seen for a few frames. In a headset, at arm's
# length, down a corridor, it reads as a thin blue scratch.
#
# WHAT IT IS NOW, and every number is a deliberate multiple of that one:
#
#   line         2.3x thicker, 1.9x the halo, 1.6x the intensity, and it holds
#                48 tics instead of 32 -- the shot is the event, so it should
#                still be dying when you lower the gun.
#   linecolor    white-hot at the muzzle running to a hard blue at the far end.
#                `rail` is one flat colour down its whole length; a real rail
#                should look hottest where it left the barrel.
#   linepulse    the core breathes once over 9 tics rather than sitting still.
#                A beam that is utterly static reads as a decal.
#   helix        4 turns per 100 units at 2x the radius, tighter spacing, and
#                1200 motes instead of 600. This is the corkscrew and it is the
#                part that says "railgun" rather than "laser".
#   beamlight    THE ONE THAT MATTERS IN A HEADSET. A segment light along the
#                whole beam, not four points on it: radius 150, intensity 3.4,
#                14 tics, falling to 0.55 at the far end. A rail fired down a
#                dark corridor should light the corridor.
#   heat         3x the radius and 2.4x the strength of `rail`, held 28 tics --
#                the air above the line keeps bending after the beam has gone.
#
# IT LAYERS WITH BD'S OWN, DELIBERATELY. The card also throws BD's
# RailgunTrailEffectMissile, which lays RailgunFlameTrailsBlue sprites down the
# same line and makes the craters and flare at the end. This profile is the hot
# core and the corkscrew; BD's is the blue bloom around it. If the two read as
# muddy rather than dense, drop ONE of them -- the `muzzlethrow` on the card, or
# the `trailprofile` on the sheet -- and not both.
trail bd_rail
  line         = 1.4, 6.6, 3.5, 48
  linecolor    = 245, 250, 255
  linecolorend = 70, 130, 255
  linelook     = 0.8, 3.0
  linepulse    = 9, 0.22, 1.6
  licks        = 0.22, 1.3, 0.09, 1.5
  helix        = rsb_rail_mote, 4.0, 6.0, 1.8
  helixmotion  = 7, 1.6, 0.35
  helixcolor   = 110, 170, 255
  helixmax     = 1200
  lights       = 6, 130, 2.4, 7
  lightcolor   = 150, 190, 255
  beamlight    = 150, 3.4, 14, 0.55
  heat         = 18, 1.2, 28
end


# ---------------------------------------------------------------- FLASHES

# THE MUZZLE, to match. `flash rail` is a 200-radius snap; this is the same
# shape half again as bright, with a longer lit-air cone down the barrel line,
# because the beam it is launching is now a great deal brighter than it was.
flash bd_rail
  light      = 320, 4.2, 5
  lightcolor = 180, 210, 255
  cone       = 14, 46, 190, 7
  conetics   = 4
  bursts     = energy_sparks_rail
  volume     = rsb_rail_snap
  exposure   = 1.1, 200, 1, 180, 210, 255
  hearing    = 0.3, 128
end
